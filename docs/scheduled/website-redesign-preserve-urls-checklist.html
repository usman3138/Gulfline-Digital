Redesign Your Website Without Losing the URLs Clients Already Useجدّد موقعك مع الحفاظ على الروابط التي يستخدمها عملاؤك

By Gulfline Digital Teamبقلم فريق جلف لاين ديجيتال 2026-12-04 · 4 min read· 4 دقائق للقراءة

Start with an inventory, not a new menu

A redesign can accidentally remove the page a client bookmarked, a tutor printed on a card or another website linked to. Before changing the navigation, list existing public URLs and identify what each one does. Include Arabic pages, blog posts, enquiry destinations and legal pages, not just items visible in the main menu. Keep a copy of the current sitemap and a crawl or local file inventory. This record is the starting point for deciding what must remain available. A cleaner homepage is not a complete redesign result if established links now lead to missing pages.

Keep stable URLs where practical

Changing colours, layout or page copy does not inherently require changing the address. Preserve working URLs when the service remains the same. If a real content reorganisation requires new URLs, Google’s migration guidance recommends preparing a mapping, configuring redirects and monitoring the result. Treat a migration as a planned task rather than an incidental side effect of a new theme. Separate hosting changes from URL changes in your brief so the developer knows what is actually moving. The owner should approve the destination for every important old page, especially those linked from ads, printed material or partner websites.

Worked example: map a small bilingual site

Imagine a site with eight English pages and six Arabic pages. Twelve addresses will stay unchanged. Two service pages need new destinations because the owner has genuinely combined two overlapping offers. The review sheet should therefore contain fourteen old URLs, twelve “keep” decisions and two explicit redirect mappings. Do not mark all fourteen as “send to homepage.” A former personal-training page should reach the relevant current service, not an unrelated generic screen. These counts describe an invented project. For this repository, existing URLs are a preservation constraint; the example explains how an owner should assess a separate migration proposal.

Test the response and the destination

Ask the developer to verify server responses, not only click links in a browser that hides the intermediate steps. Check that a permanent move uses an appropriate permanent redirect, that there is no loop and that the destination exists. Keep internal links, canonical URLs and sitemap entries aligned with the final addresses. Test with and without common query parameters if campaigns use them. A page can load visually while still exposing an outdated canonical tag or pointing its language switch to the wrong place. Save the evidence from the actual server configuration; a proposed redirect rule in a document is not proof that it works.

Recheck the customer journey in Arabic

Choose one realistic task and perform it in both languages: find the service, understand the price conditions and send an enquiry. Check right-to-left layout, phone number direction, labels and links to policies. Review shared footer links too, because a redesign often replaces a whole footer at once. If you distribute a new printed contact card, a code from the EasyToolbox QR generator should point to a stable customer-facing URL. Scan an old card as well. A redesign should improve the journey for existing clients, not require them to discover every new route from scratch.

Plan monitoring and a rollback decision

Before launch, keep a restorable copy and decide who can restore it if critical pages or enquiry routes fail. After launch, inspect important URLs and monitor errors and search reporting over time without promising instant ranking stability. Record what was locally tested, what was checked on the live server and what remains unverified. If a contact link is broken, fix that before debating minor visual differences. Keep the mapping sheet with the project handover so future suppliers understand why old addresses still matter. A successful redesign preserves useful access while making the current service easier to understand and use.

ابدأ بالحصر لا بالقائمة الجديدة

قد يزيل التجديد صفحة حفظها عميل أو طبعها مدرس على بطاقة أو ربط بها موقع آخر. قبل تعديل القائمة، احصر الروابط العامة ووظيفة كل منها، بما فيها العربية والمقالات والاستفسارات والسياسات، لا العناصر الظاهرة فقط. احتفظ بخريطة الموقع وحصر الملفات أو الزحف الحالي. هذا أساس قرار ما ينبغي إبقاؤه متاحاً. ليست الصفحة الرئيسية الأجمل نتيجة مكتملة إذا أصبحت الروابط المعروفة تقود لصفحات مفقودة.

حافظ على الروابط المستقرة قدر الإمكان

لا يستلزم تغيير الألوان أو التخطيط أو النص تغيير العنوان. احتفظ بالروابط العاملة ما دامت الخدمة نفسها. وإذا تطلب تنظيم حقيقي عناوين جديدة، فتوصي إرشادات Google بإعداد خريطة وتحويلات ومراقبة النتيجة. اجعل النقل مهمة مخططة لا أثراً جانبياً لقالب جديد. افصل تغيير الاستضافة عن تغيير الروابط في الموجز، واعتمد وجهة كل صفحة مهمة، خصوصاً المرتبطة بالإعلانات والمطبوعات ومواقع الشركاء.

مثال عملي: مطابقة موقع صغير ثنائي اللغة

لنفترض موقعاً من ثماني صفحات إنجليزية وست عربية. سيبقى اثنا عشر عنواناً، وتتغير صفحتا خدمة لأن المالك دمج عرضين متداخلين فعلياً. ينبغي أن يضم الجدول أربعة عشر رابطاً قديماً واثني عشر قرار إبقاء وتحويلين محددين. لا تجعل القرار لكل الصفحات «إلى الرئيسية». يجب أن تصل صفحة التدريب الشخصي القديمة للخدمة الحالية المناسبة. هذه أعداد مشروع افتراضي؛ وفي هذا المستودع تُحفظ الروابط القائمة، والمثال يشرح تقييم مقترح نقل مستقل.

اختبر الاستجابة والوجهة

اطلب فحص استجابة الخادم لا الاكتفاء بالنقر في متصفح يخفي الخطوات. راجع التحويل الدائم المناسب وغياب الحلقات ووجود الوجهة. طابق الروابط الداخلية والروابط الأساسية وخريطة الموقع مع العناوين النهائية. اختبر معاملات الحملات الشائعة عند استخدامها. فقد تبدو الصفحة سليمة بينما تحمل رابطاً أساسياً قديماً أو تبدّل اللغة لوجهة خاطئة. احفظ نتيجة إعداد الخادم الفعلي؛ فقاعدة مقترحة في مستند ليست دليلاً على نجاح التشغيل.

أعد فحص الرحلة بالعربية

اختر مهمة واقعية باللغتين: العثور على الخدمة وفهم شروط السعر وإرسال استفسار. راجع اتجاه اليمين لليسار ورقم الهاتف والتسميات والسياسات. افحص التذييل أيضاً، إذ قد يُستبدل بالكامل. وإذا طبعت بطاقة جديدة، فليوجّه رمز من أداة QR في إيزي تول بوكس إلى رابط عام مستقر. امسح بطاقة قديمة كذلك. ينبغي للتجديد تحسين رحلة العملاء الحاليين لا إجبارهم على اكتشاف المسارات من البداية.

خطّط للمراقبة وقرار التراجع

احتفظ بنسخة قابلة للاستعادة وحدّد من يعيدها إذا تعطلت صفحات مهمة أو مسارات الاستفسار. بعد الإطلاق افحص الروابط وراقب الأخطاء وتقارير البحث بمرور الوقت دون ضمان استقرار فوري للترتيب. ميّز ما اختُبر محلياً وما فُحص على الخادم وما بقي مجهولاً. أصلح رابط التواصل قبل مناقشة فروق جمالية صغيرة. وأرفق جدول المطابقة بالتسليم كي يفهم المورد اللاحق أهمية العناوين القديمة. ينجح التجديد حين يحفظ الوصول المفيد ويسهّل فهم الخدمة الحالية واستخدامها.
