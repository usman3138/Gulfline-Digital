# Architecture

## Overview

A static website. Hostinger serves the files in this repo exactly as they are; there is no server code and no build step.

```
Browser  ->  Hostinger (gulflinedigital.com)  <-  git push to main (GitHub)
   |
   +-> PayPal (paypal.me link built by checkout.html)
   +-> WhatsApp (click-to-chat links)
   +-> Supabase (sign-in — prepared, not switched on)
   +-> Google AdSense, Google Fonts
```

## Pages

| File | What |
|---|---|
| `index.html` | Home: hero, pricing card, services, our work, "From the blog" |
| `services.html` | All services |
| `about.html`, `contact.html`, `privacy.html`, `terms.html` | Standard pages |
| `checkout.html` | Order form and payment |
| `account.html` | Sign in / sign up |
| `ar/*.html` | Arabic-first copies of home, about, services, contact, privacy, terms |
| `blog/*.html` | 10 articles + `index.html` + `rss.xml` |

Each page is self-contained: its CSS and JavaScript are inside the HTML file. Shared scripts are only `auth-nav.js`, `supabase-config.js` and `construction-banner.js`.

## Two languages

Every text block exists twice, marked `data-lang="en"` and `data-lang="ar"`; a toggle shows one and switches the page to right-to-left for Arabic. The `ar/` folder holds Arabic-first copies so search engines get a proper Arabic URL, linked with hreflang tags.

## Checkout

`checkout.html` lists the products and add-ons with prices in AED. The total is converted to USD and the "Pay now" button opens a `paypal.me` link for that amount. There is no payment backend: the site itself records nothing about the order.

## Sign-in

`account.html` uses the Supabase JavaScript client from a CDN. `supabase-config.js` still holds placeholders, so `supabaseClient` is `null` and sign-in is inactive. `auth-nav.js` swaps the menu link to "Sign out" when a session exists.

## Blog

Hand-finished static HTML with BlogPosting and FAQPage structured data. The first 10 posts were generated by a one-off script that is not in this repo; new posts are made by copying an existing post.

### Scheduled publishing — implemented locally 2026-11-04

`docs/scheduled/manifest.json` describes 13 staged bilingual posts. `publish.py` uses Dubai time, publishes the earliest due unpublished entry, and permits at most one publication per Dubai calendar day. It prepares and validates the bilingual index card, Blog JSON-LD, `blog/rss.xml`, `sitemap.xml` and `CHANGELOG.md` before writing. The published HTML uses the actual publication date; the source review date remains 4 November. The staged HTML is retained as a review/recovery source. A date stamp and exclusive local lock supplement the workflow's concurrency group. Partial write failures stop subsequent publication for inspection rather than silently duplicating discovery entries.

`.github/workflows/publish-scheduled.yml` runs at 08:17, 12:17 and 16:17 Dubai, with manual dispatch available. It runs regression tests, publishes, checks the site and staging, then commits only publication outputs and pushes the branch. This is future automation; no commit, push or deployment was executed during implementation. See [operation and recovery](scheduled/README.md).

`family.css` is linked after existing styles on every page; identical bilingual footer fragments link the related tool site, money-tracker site and three apps. Blog index/new post controls use `site-language.js` to change `lang`, `dir`, visibility and accessible labels without storage. The new posts retain the existing article template's analytics, ads, WhatsApp button and banner. Their illustrations are inline original SVG, with no new stock imagery. New article JSON-LD describes both languages and omits the old template's unrelated FAQs. Existing public URLs remain intact.
